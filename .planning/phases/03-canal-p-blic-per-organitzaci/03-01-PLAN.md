<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client -> get_complaint_by_tracking_code RPC | `p_code` and `p_organization_id` are client-supplied but passed as parameterized RPC args (no SQL injection); the org id was itself resolved from the URL slug via the SECURITY DEFINER slug RPC, not free-form attacker input |
| anonymous client -> attachments/messages insert/select | `complaint_id` is client-supplied; new EXISTS-join requires it to reference a real complaint row, but the UUID itself remains the bearer secret (same model as tracking_code) |
| SECURITY DEFINER RPC -> complaints table | RPC bypasses RLS by design; returns at most the rows matching BOTH code and org — no enumeration of other tenants' complaints possible |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering (bypass of org filter) | residual 1-arg get_complaint_by_tracking_code(text) overload | mitigate | `drop function if exists get_complaint_by_tracking_code(text);` runs BEFORE creating the 2-arg version (Pitfall 2); Task 2 verifies `pronargs = 2` and exactly one row |
| T-03-02 | Information Disclosure | tracking-code lookup returning a row from a different organization | mitigate | 2-arg RPC filters `where tracking_code = upper(p_code) and organization_id = p_organization_id` server-side — a mismatched org returns zero rows regardless of any client bug (PUBLIC-03) |
| T-03-03 | Information Disclosure / Tampering | attachments/messages readable/insertable for any complaint_id from any org (migration-001 `using (true)` policies) | mitigate | EXISTS-join RLS (Pattern 3) requires the referenced complaint to exist; closes the literal `using (true)`/`with check (true)` gap left by migration 005 |
| T-03-04 | Information Disclosure | full per-tenant column-level scoping of attachments/messages | accept | attachments/messages have no organization_id column; complaint_id UUID (122 bits) is treated as an unguessable bearer token, consistent with tracking_code; full column-level scoping deferred to v1.1 per RESEARCH.md Open Question 2 |
| T-03-05 | Tampering | SQL injection via slug/code/org id | accept | All values pass through Supabase `rpc()` parameterized calls (`p_code`/`p_organization_id`), never string-concatenated SQL (ASVS V5, RESEARCH.md Security Domain) |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this phase (RESEARCH.md Package Legitimacy Audit: N/A) — no install task, no supply-chain surface introduced |
