New function to add, per 02-RESEARCH.md "supabase.js addition":

  export async function signUpOrganization({ companyName, fullName, email, password }) {
    const { data, error } = await supabase.auth.signUp({
      email,
      password,
      options: {
        data: { company_name: companyName, full_name: fullName },
      },
    });

    return {
      user: data?.user ?? null,
      needsConfirmation: !!data?.user && !data?.session,
      error,
    };
  }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form -> supabase.auth.signUp() | User-supplied companyName/fullName/email/password sent as raw_user_meta_data; consumed server-side only by the migration-006 trigger (plan 02-01) |
| Signup page -> /admin redirect | Only reachable if Supabase Auth actually returns a session (i.e., email confirmation not required or already done) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Information Disclosure | errorGeneric message echoes err.message from Supabase | accept | Supabase Auth error messages (e.g. "Password should be at least 6 characters") are generic, non-sensitive, and already echoed verbatim in existing Login.jsx (`'Error en iniciar sessió: ' + err.message`) - consistent with established pattern, no new exposure |
| T-02-06 | Spoofing | Anyone can call signUpOrganization to create an arbitrary number of organizations (no CAPTCHA) | accept | Not in REQUIREMENTS.md scope for this phase (02-RESEARCH.md flags Turnstile as a recommendation, not a blocking requirement); Supabase Auth's own rate limiting on signUp applies. Revisit in a later phase if abuse observed. |
| T-02-07 | Tampering | Client could send arbitrary extra keys in raw_user_meta_data | accept | The trigger (migration 006, plan 02-01) only reads company_name and full_name; any other client-supplied keys are ignored by handle_new_user() and have no effect on organization_id assignment |
</threat_model>
