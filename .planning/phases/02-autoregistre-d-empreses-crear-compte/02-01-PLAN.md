```sql
create or replace function handle_new_user()
returns trigger as $$
begin
  insert into profiles (id, role, full_name)
  values (new.id, 'manager', new.raw_user_meta_data->>'full_name')
  on conflict (id) do nothing;
  return new;
end;
$$ language plpgsql security definer;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function handle_new_user();
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (signUp) -> auth.users insert -> trigger | `raw_user_meta_data` is client-supplied (untrusted) but only ever used to decide "create new org for THIS new user" — cannot reference or modify any existing organization |
| trigger -> organizations / profiles tables | `security definer` bypasses RLS by design — must only ever insert rows scoped to `new.id` (the just-created user) and a freshly generated `org_id` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | handle_new_user() trigger (006) | mitigate | Branch strictly on presence of non-empty `raw_user_meta_data->>'company_name'`; org_id is always freshly generated via `gen_random_uuid()` default, never attacker-supplied — worst case a self-signup user becomes superadmin of their own brand-new empty org, which is the intended behavior |
| T-02-02 | Tampering | search_path hijacking on security definer function | mitigate | `set search_path = public` added to handle_new_user (006); slugify/generate_unique_org_slug use `extensions.unaccent` fully-qualified |
| T-02-03 | Repudiation/Tampering | Duplicate org creation on retried trigger invocation | mitigate | Idempotency guard `if exists (select 1 from profiles where id = new.id) then return new; end if;` at top of handle_new_user (Pitfall 2) |
| T-02-04 | Information Disclosure | slug enumeration via /canal/:slug | accept | Out of scope for this phase (Phase 3 concern); get_organization_by_slug() already returns minimal fields (id, name, slug) per migration 005 |
</threat_model>
